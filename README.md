# JKB

JKB — компактная однодосочная Kanban-система для небольшой команды. В одном
Go-приложении живут встроенный Vue-интерфейс, SQLite, HTTP API и remote MCP
endpoint для AI-агентов. База, вложения и аватары хранятся в одном локальном
data volume.

Проект сознательно не пытается быть ещё одной Taiga или Jira: одна доска,
минимум инфраструктуры и никаких обязательных S3, Redis, очередей или отдельных
frontend-контейнеров.

## Возможности

- одна Kanban-доска с настраиваемыми колонками и drag-and-drop;
- проекты для группировки и фильтрации задач;
- группы пользователей, исполнители и теги;
- описания и комментарии с безопасным Markdown;
- вложения к задачам и проектам в локальном хранилище;
- профили с отображаемым именем и аватаром;
- роли `admin` и `member`;
- персональные API-токены с отдельными правами чтения и изменения;
- remote MCP для агентов;
- история изменений карточек и optimistic locking;
- health checks, явные миграции и административный CLI;
- создание и восстановление согласованных резервных копий из панели администратора.

## Границы проекта

- В системе одна доска. Проекты не создают отдельные доски, а используются как
  фильтр и логическая область задач.
- Самостоятельной регистрации нет. Пользователей создаёт администратор через
  CLI или административный интерфейс.
- Поддерживается ровно один экземпляр JKB. SQLite и локальные файлы не предназначены
  для одновременной работы нескольких реплик.
- Data volume должен находиться на локальной файловой системе. NFS, SMB и другие сетевые
  файловые системы не поддерживаются.
- PostgreSQL volumes и backup-архивы прежних версий несовместимы с SQLite-релизом;
  встроенного production-импортера нет.
- HTTPS завершается на reverse proxy перед приложением.

## Архитектура

```text
Браузер ───────┐
               ├──> JKB (Go HTTP server) ───> /var/lib/jkb/jkb.sqlite
MCP-клиент ────┘          │
                          └───────────────> /var/lib/jkb/files
```

Frontend собирается Vite и встраивается в Go-бинарник. В production достаточно одного
контейнера JKB и одного persistent volume `/var/lib/jkb`.

Готовый multi-platform образ публикуется в GitHub Container Registry:
[`ghcr.io/reansn0w/justkb`](https://github.com/ReanSn0w/justkb/pkgs/container/justkb).
Для обычного развёртывания используйте `latest`, а для воспроизводимого — тег
конкретного релиза, например `ghcr.io/reansn0w/justkb:1.0.0`.

Основной стек:

- Go 1.26;
- Vue 3, TypeScript, Pinia и Vue Router;
- Bulma без собственного CSS;
- SQLite через pure-Go драйвер `modernc.org/sqlite`;
- официальный Go SDK для MCP.

## Быстрый запуск через Docker Compose

Понадобятся Docker и Docker Compose.

1. Подготовьте конфигурацию:

   ```sh
   cp .env.example .env
   ```

   Для публичного развёртывания задайте внешний `JKB_PUBLIC_URL` и оставьте
   `JKB_COOKIE_SECURE=true`.

2. Загрузите готовый образ:

   ```sh
   docker compose pull app
   ```

   По умолчанию Compose использует `ghcr.io/reansn0w/justkb:latest`. Чтобы
   закрепить версию, задайте, например,
   `JKB_IMAGE=ghcr.io/reansn0w/justkb:1.0.0` в `.env`. Для сборки текущего
   исходного кода вместо опубликованного образа выполните `docker compose build app`.

3. Создайте и запустите постоянный контейнер приложения:

   ```sh
   docker compose up -d app
   ```

4. Примените миграции внутри работающего контейнера и перезапустите приложение:

   ```sh
   docker compose exec app /usr/local/bin/jkb-migrate up
   docker compose restart app
   ```

5. Создайте первого администратора:

   ```sh
   docker compose exec app /usr/local/bin/jkb-admin user add \
     --role admin \
     --display-name "Administrator" \
     admin
   ```

   Команда интерактивно запросит пароль и его подтверждение. Пароль не
   передаётся через аргументы и не выводится в терминал.

По умолчанию JKB будет доступен на [http://localhost:8080](http://localhost:8080).
База SQLite, вложения и аватары попадут в единый Compose volume `data`.
При старте контейнер исправляет владельца `/var/lib/jkb`, затем запускает приложение
под непривилегированным UID `10001`. Поэтому существующий volume или bind mount,
изначально созданный root на Linux, не требует ручного `chown`.

Проверить состояние контейнеров:

```sh
docker compose ps
curl --fail http://localhost:8080/health/ready
```

Не заменяйте `docker compose exec app ...` на
`docker compose run --rm app ...` в развёрнутом стенде. Reverse proxy с
service discovery через Docker socket может увидеть одноразовый
контейнер как экземпляр сервиса и направить на него часть трафика.
До завершения миграции и успешной readiness-проверки не направляйте
на обновляемый контейнер внешний трафик.

## Административный CLI

`jkb-admin` предназначен для bootstrap и операций, которые не требуют отдельного
веб-интерфейса.

Создание обычного пользователя:

```sh
docker compose exec app /usr/local/bin/jkb-admin user add \
  --display-name "Ada Lovelace" \
  --email ada@example.test \
  ada
```

Роль по умолчанию — `member`. Для администратора передайте `--role admin`.
Отображаемое имя по умолчанию совпадает с логином, email необязателен.
Сброс пароля с отзывом всех web-сессий пользователя:

```sh
docker compose exec app /usr/local/bin/jkb-admin user password admin
```

Просмотр профиля и изменение активности:

```sh
docker compose exec app /usr/local/bin/jkb-admin user show admin
docker compose exec app /usr/local/bin/jkb-admin user disable alice
docker compose exec app /usr/local/bin/jkb-admin user enable alice
```

`user show` выводит ID, логин, отображаемое имя, email, роль, активность и
группы. Хеш пароля, сессии и API-токены не выводятся. Отключить последнего
активного администратора нельзя.

Справка:

```sh
docker compose exec app /usr/local/bin/jkb-admin --help
docker compose exec app /usr/local/bin/jkb-admin user add --help
docker compose exec app /usr/local/bin/jkb-admin user password --help
docker compose exec app /usr/local/bin/jkb-admin user show --help
```

## Remote MCP

MCP endpoint находится по адресу:

```text
https://jkb.example.com/mcp
```

Персональный токен выпускается в настройках профиля на вкладке «API-токены».
Клиент должен передавать его в HTTP-заголовке:

```http
Authorization: Bearer jkb_pat_…
```

Доступные scopes:

- `cards:read` — чтение доски, справочников, проектов, задач и комментариев;
- `cards:write` — создание и изменение задач, комментариев и связанных данных.

Инструмент `list_card_movements` позволяет агенту подготовить отчёт о переходах карточек между
колонками за предыдущие 24 часа или произвольный период. Без фильтров отчёт включает всех
пользователей; при необходимости его можно ограничить инициатором, текущим исполнителем, проектом,
группой или конкретной карточкой.

Не добавляйте токены в URL, Git-репозиторий или общие конфигурационные файлы.
Полный перечень MCP tools и формат ошибок описаны в [CONTRACT.md](CONTRACT.md#5-mcp-api).

## HTTP API

- REST API: `/api/v1`;
- remote MCP: `/mcp`;
- liveness: `/health/live`;
- readiness: `/health/ready`.

Веб-интерфейс и REST API используют cookie-сессию и CSRF-защиту. Персональные
API-токены используются MCP endpoint. Контракт сущностей, REST endpoints, ролей
и ошибок находится в [CONTRACT.md](CONTRACT.md).
Агент может определить владельца токена и его группы через `get_current_user`, а также
читать обсуждения карточек и проектов через `list_comments`.

| -------------------------- | ----------: | ---------------------- | -------------------------------------------- |
| `JKB_DATABASE_PATH`        |         нет | `./storage/jkb.sqlite` | путь к файлу SQLite                          |
| `JKB_STORAGE_PATH`         |         нет | `./storage/files`      | каталог вложений и аватаров                  |
| `JKB_SYSTEM_NAME`          |         нет | `JKB`                  | имя системы в web-интерфейсе                 |

| `JKB_PUBLIC_URL`           |         нет | —                      | зарезервированный внешний origin приложения  |
| `JKB_COOKIE_SECURE`        |         нет | `true`                 | отправлять session cookie только через HTTPS |
| `JKB_ATTACHMENT_MAX_BYTES` |         нет | `26214400`             | максимальный размер вложения                 |

входа и в заголовке вкладки. Технические идентификаторы (`JKB-42`,
`jkb_pat_...`, имена cookie и backup-файлов) остаются стабильными.

## Обновление

Перед обновлением сделайте резервную копию, затем:

```sh
docker compose pull app
docker compose up -d app
docker compose exec app /usr/local/bin/jkb-migrate up
docker compose restart app
curl --fail http://localhost:8080/health/ready
```

Для перехода на определённый релиз сначала измените `JKB_IMAGE` в `.env`,
например на `ghcr.io/reansn0w/justkb:1.0.0`, и затем выполните те же команды.

Миграции выполняются отдельно и не запускаются скрыто при старте приложения.
Это позволяет контролировать порядок deployment. `jkb-migrate down` используйте
только после проверки конкретной rollback-миграции и резервной копии.

## Архив и автоматические правила

Пункт **Архив** расположен в header после **Проекты**. Это общий таймлайн карточек
и проектов с поиском, фильтрами, раскрытием карточек проектной операции и режимом
полной истории. Архивные объекты доступны для чтения; перед изменением их нужно
восстановить. Восстановление проекта доступно администратору и предлагает два
варианта: только проект либо проект с карточками, архивированными вместе с ним.
Ранее отдельно архивированные карточки остаются в архиве.

Администратор настраивает правила в **Настройки системы → Архивация**:

- один столбец «Готово» для прогресса проектов и автоархивации карточек;
- независимые переключатели для карточек и проектов;
- отдельные сроки от 1 до 3650 дней, по умолчанию 3;
- предпросмотр количества уже подходящих объектов перед сохранением.

Оба правила первоначально **выключены**. День означает 24 часа. Срок карточки
идёт от входа в выбранный столбец; правки текста и перестановки внутри столбца
его не меняют. Проект должен быть полностью завершён непрерывно в течение своего
срока; пустые проекты не подходят. Архивные карточки продолжают участвовать в
прогрессе, поэтому очистка доски не уменьшает процент готовности.

При смене столбца отсчёт начинается заново. При изменении срока или включении
правила учитывается накопленное время. Восстановление даёт объекту новый срок.
Автоматика работает внутри Go-процесса при запуске и каждые 5 минут: сначала
проекты с активными карточками, затем отдельные карточки. Backup/restore исключает
одновременную работу обработчика. Ошибки прохода видны в логах `archive pass`.

Обновление требует явного `docker compose exec app /usr/local/bin/jkb-migrate up`
и перезапуска приложения. Миграция сохраняет историю и назначения, начинает
неизвестные сроки от момента обновления и помечает неизвестные старые даты
архивации проектов. Откат с историей архива запрещён, чтобы не потерять данные.

## Резервное копирование

Администратор может скачать полный архив или восстановить его на вкладке
«Резервные копии» в системных настройках. Архив содержит online snapshot SQLite,
manifest с версией схемы, вложения и аватары. Во время snapshot и restore приложение
временно блокирует остальные запросы. Перед restore проверяются SQLite-файл и версия
схемы; при ошибке сервис автоматически восстанавливает прежние базу и файлы.

Для внешнего инфраструктурного backup можно скопировать единый data volume. Приложение
нужно остановить, чтобы в копию не попали рассинхронизированные SQLite/WAL-файлы:

```sh
docker compose stop app
docker run --rm --user 0 \
  --volumes-from "$(docker compose ps -q app)" \
  -v "$PWD":/backup \
  alpine:3.22 tar -C /var/lib/jkb -czf /backup/jkb-data.tar.gz .
docker compose start app
```

Восстанавливайте архив в пустой volume до запуска `app`. Резервная
копия, восстановление которой никогда не проверяли, — это, строго говоря,
довольно оптимистичная гипотеза.

## Локальная разработка

Требования:

- Go 1.26;
- Node.js 24 и npm.

Установить frontend-зависимости:

```sh
npm ci
```

Примените миграции к локальному SQLite-файлу и запустите backend:

```sh
go run ./cmd/jkb-migrate up
JKB_COOKIE_SECURE=false go run ./cmd/jkb
```

По умолчанию база будет создана в `./storage/jkb.sqlite`, а файлы — в `./storage/files`.
Для другого каталога задайте `JKB_DATABASE_PATH` и `JKB_STORAGE_PATH`.

Для разработки интерфейса запустите Vite во втором терминале:

```sh
npm run dev
```

Vite проксирует `/api` и `/mcp` на `http://localhost:8080`.

Production frontend собирается и встраивается автоматически через Dockerfile.
Для ручной сборки единого бинарника:

```sh
npm run build
go build ./cmd/jkb
```

## CI и публикация образов

GitHub Actions запускает backend- и frontend-проверки для pull request, `master`
и тегов вида `v1.0.0`. Контейнер собирается только после успешного прохождения
обоих наборов проверок для `linux/amd64` и `linux/arm64`.

- push в `master` публикует `ghcr.io/reansn0w/justkb:latest` и тег `sha-*`;
- push тега `v1.0.0` публикует `1.0.0`, `1.0`, `1` и `latest`;
- pull request проверяет сборку образа, но ничего не публикует.

Опубликованный образ доступен для `docker pull` без входа в GHCR.

Создание релиза:

```sh
git tag -a v1.0.0 -m "v1.0.0"
git push origin v1.0.0
docker pull ghcr.io/reansn0w/justkb:1.0.0
```

## Ориентир по ресурсам

JKB больше не требует отдельного процесса базы. Замер 1 ноября 2026 года для
`ghcr.io/reansn0w/justkb:sha-b530c32` на Apple Silicon в OrbStack после запуска,
восстановления backup и периода простоя:

| Метрика                             | Значение |
| ----------------------------------- | -------- |
| Логический размер образа            | 55,0 MiB |
| Idle CPU                            | 0,00 %   |
| Память контейнера по `docker stats` | 139 MiB  |

Локально сохранённые образы прежних `app` и `postgres:17-alpine` занимали
в сумме 462,8 MiB. Новый одноконтейнерный вариант меньше на 88,1 %. Старый
PostgreSQL-экземпляр не запускался ради замера RAM: его данные оставлены нетронутыми.
Числа зависят от архитектуры, runtime контейнеров и нагрузки; это ориентир, а не SLA.

### Оформление и установка на телефон

`JKB_SYSTEM_NAME` задаёт также заголовок HTML, имя в manifest и название приложения
на домашнем экране. Необязательный `JKB_ICON_COLOR` задаёт фон иконки в формате
`#RRGGBB` (например, `#7C3AED`). Без переменной, при пустом значении или пробелах
используется `#2563EB`: существующая конфигурация продолжает работать после
обновления. Некорректный непустой цвет вызывает ошибку конфигурации.

После изменения окружения пересоздайте контейнер с новыми параметрами. Пересборка
образа не нужна. Цвет знака автоматически выбирается по контрасту; геометрия
иконки и тема интерфейса сохраняются. Иконки и manifest формируются при запуске,
их ссылки содержат отпечаток оформления.

На iPhone откройте сайт в Safari, выберите «Поделиться» → «На экран Домой»
и включите открытие как веб-приложения, если система предлагает такой выбор.
Запуск с домашнего экрана использует standalone-режим без панелей браузера.
Обновление уже установленной иконки зависит от ОС; иногда требуется удалить
ярлык и добавить приложение заново. Отдельные экземпляры JKB можно различать
именем и цветом; каждый экземпляр по-прежнему содержит одну общую доску.

Фильтры доски сохраняются в URL. Ссылку можно скопировать, обновить страницу или
вернуться из карточки кнопкой «Доска» либо через историю браузера. Ввод поиска
заменяет текущую запись истории, поэтому Back не перебирает каждый символ.
Подробнее: [правила навигации](docs/navigation.md).

Переходы страниц и заголовков карточек/проектов выполняет браузер через View
Transitions. При отсутствии API и при включённом уменьшении движения навигация
работает без анимации. Фильтрация и drag-and-drop не запускают страничный эффект.
