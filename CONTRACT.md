# JKB — контракт продукта и API

Этот документ фиксирует границы MVP, модель данных, HTTP API и MCP API. Если реализация и контракт расходятся, контракт считается источником истины до явного изменения.

## 1. Границы MVP

JKB — одна общая kanban-доска для небольшой команды.

В MVP входят:

- один глобальный набор колонок;
- проекты как крупные направления работы;
- карточки с группой, исполнителем, тегами, сроком и вложениями;
- фильтрация по проекту, группе, исполнителю, тегам, колонке и тексту;
- локальное хранение вложений на диске сервера;
- веб-интерфейс с сессионной авторизацией;
- персональные API-токены;
- remote MCP endpoint для работы агентов с карточками;
- журнал изменений карточек.

В MVP не входят несколько досок, уведомления, комментарии, OAuth-провайдер, публичные доски и объектное хранилище.

## 2. Термины и права

### 2.1. Роли

- `admin` управляет пользователями, группами, колонками, проектами и тегами;
- `member` читает всю доску и работает с карточками.

Группы — способ классификации и фильтрации, а не граница видимости. Авторизованный пользователь видит все карточки. Исполнитель не обязан состоять в назначенной карточке группе.

### 2.2. Состояние пользователя

Неактивный пользователь не может войти, использовать сессию или API-токен. Деактивация не удаляет его из истории и не снимает автоматически с карточек.

## 3. Модель данных

Все идентификаторы во внешних API — UUID. Время передаётся в UTC в формате RFC 3339. Поля `created_at` и `updated_at` присутствуют у всех изменяемых сущностей.

### 3.1. Основные сущности

| Сущность | Обязательные поля | Опциональные поля |
|---|---|---|
| User | `id`, `username`, `display_name`, `role`, `is_active` | `email`, `avatar_url` |
| Group | `id`, `name`, `color` | `description` |
| Column | `id`, `name`, `position` | `wip_limit` |
| Project (`Epic` в API) | `id`, `name`, `color`, `is_archived`, `version`, `card_count`, `completed_card_count` | `description`, `attachments` |
| Tag | `id`, `name`, `color` | — |
| Card | `id`, `number`, `title`, `description`, `column_id`, `position`, `version`, `is_archived` | `epic_id`, `group_id`, `assignee_id`, `due_at` |
| Attachment | `id`, `original_name`, `media_type`, `size`, `created_by` | `card_id` или `epic_id` |
| Comment | `id`, `body`, `author_user_id`, `created_at`, `updated_at` | `card_id` или `epic_id`, `author_token_id` |
| API token | `id`, `user_id`, `name`, `token_prefix`, `scopes` | `expires_at`, `last_used_at`, `revoked_at` |
| Activity | `id`, `card_id`, `actor_user_id`, `action`, `changes` | `actor_token_id` |

`Card.number` — неизменяемый человекочитаемый номер. Карточка показывается как `JKB-42`.

`Card.version` увеличивается при каждом изменении. Мутирующие операции принимают `expected_version` и возвращают конфликт, если карточка уже изменена.

### 3.2. Связи

- пользователь может состоять в нескольких группах;
- карточка имеет не более одного проекта, одной группы и одного исполнителя;
- карточка может иметь несколько тегов и вложений;
- проект имеет подробное Markdown-описание и может содержать несколько вложений;
- вложение принадлежит ровно одной карточке или одному проекту;
- комментарий принадлежит ровно одной карточке или одному проекту и поддерживает Markdown;
- архивный проект остаётся у существующих карточек, но не предлагается для новых;
- удаление колонки с карточками запрещено до перемещения её карточек.

## 4. HTTP API

### 4.1. Общие правила

- базовый путь: `/api/v1`;
- тела запросов и ответов: JSON, кроме загрузки и скачивания файлов;
- веб-клиент аутентифицируется через `HttpOnly`, `Secure`, `SameSite=Lax` cookie;
- изменяющие cookie-авторизованные запросы защищаются CSRF-токеном;
- списки используют cursor pagination с `limit` не более 100;
- `DELETE` для токенов и вложений возвращает `204 No Content`;
- архивирование карточек и проектов является обратимой мутацией, а не `DELETE`.

Формат успешного списка:

```json
{
  "items": [],
  "next_cursor": null
}
```

Формат ошибки:

```json
{
  "error": {
    "code": "card_version_conflict",
    "message": "Card was changed by another actor",
    "details": {},
    "request_id": "01J..."
  }
}
```

Коды ошибок стабильны и пригодны для машинной обработки. Ожидаемые статусы: `400`, `401`, `403`, `404`, `409`, `413`, `422`, `429`, `500`.

### 4.2. Auth и профиль

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/auth/login` | Создать веб-сессию |
| `POST` | `/auth/logout` | Завершить текущую сессию |
| `GET` | `/auth/me` | Получить профиль, группы и CSRF-токен |
| `PATCH` | `/auth/profile` | Изменить своё отображаемое имя |
| `POST` | `/auth/avatar` | Загрузить свой аватар (`multipart/form-data`, поле `file`) |
| `DELETE` | `/auth/avatar` | Удалить свой аватар |
| `PUT` | `/auth/password` | Сменить свой пароль |

### 4.3. Управление

| Ресурс | Пути | Доступ |
|---|---|---|
| Users | `GET, POST /users`; `GET, PATCH /users/{id}`; `PUT /users/{id}/groups`; `PUT /users/{id}/password` | Чтение — все, изменение — admin |
| Groups | `GET, POST /groups`; `GET, PATCH /groups/{id}` | Чтение — все, изменение — admin |
| Columns | `GET, POST /columns`; `PATCH /columns/{id}`; `POST /columns/reorder`; `DELETE /columns/{id}` | Чтение — все, изменение — admin |
| Projects (`epics`) | `GET, POST /epics`; `GET, PATCH /epics/{id}`; `POST /epics/{id}/attachments` | Чтение — все, изменение — admin; вложения — все |
| Tags | `GET, POST /tags`; `GET, PATCH /tags/{id}` | Чтение — все, изменение — admin |
| Backups | `POST /admin/backups`; `POST /admin/backups/restore` | Только admin |
| System | `GET /system` | Публично; возвращает имя системы |

Первый admin создаётся после миграций командой `jkb-admin user add --role admin --display-name "Administrator" admin`. Эта же команда создаёт обычных пользователей (`member` по умолчанию); пароль вводится и подтверждается интерактивно. `jkb-admin user password <username>` сбрасывает пароль и отзывает web-сессии этого пользователя. `user show`, `user enable` и `user disable` позволяют проверить профиль и изменить активность; последнего активного admin нельзя отключить или понизить до `member`. Сервер не имеет общедоступного setup endpoint.

`GET /users/{id}/avatar` возвращает аватар авторизованному участнику. Аватары хранятся локально в `avatars` внутри каталога хранилища; принимаются JPEG, PNG, GIF и WebP размером до 5 МБ.

`POST /admin/backups` возвращает `tar.gz` с manifest, согласованным online snapshot SQLite и локальными файлами. `POST /admin/backups/restore` принимает этот архив в `multipart/form-data` (`file`, `confirmation=RESTORE`) и заменяет текущие данные. Restore разрешён только при совпадении версии схемы. Операции выполняются под maintenance-lock; перед restore сервис валидирует SQLite-файл, создаёт внутренний rollback-снимок текущей базы и сохраняет прежний каталог файлов до успешного завершения. PostgreSQL-архивы прежнего формата отклоняются.

### 4.4. Карточки

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/cards` | Список и фильтрация |
| `POST` | `/cards` | Создать карточку |
| `GET` | `/cards/{id}` | Получить карточку с тегами и вложениями |
| `PATCH` | `/cards/{id}` | Изменить поля карточки |
| `POST` | `/cards/{id}/move` | Изменить колонку и/или позицию |
| `POST` | `/cards/{id}/archive` | Архивировать |
| `POST` | `/cards/{id}/restore` | Восстановить |
| `GET` | `/cards/{id}/activity` | Получить журнал изменений |

Фильтры `GET /cards`:

- `epic_id`, включая специальное значение `none`;
- `group_id`, включая `none`;
- `assignee_id` совпадает с любым исполнителем, `me` — с текущим пользователем, `none` — с карточками без исполнителей;
- повторяемый `tag_id`;
- `column_id`;
- `q` для поиска по номеру, заголовку и описанию;
- `archived`, по умолчанию `false`.

Фильтры объединяются условием AND. Несколько `tag_id` означают, что у карточки должен быть каждый указанный тег.

Пример создания:

```json
{
  "title": "Implement PAT authentication",
  "description": "Store only a digest of the token.",
  "column_id": "uuid",
  "epic_id": "uuid",
  "group_id": "uuid",
  "assignee_ids": ["uuid"],
  "tag_ids": ["uuid"],
  "due_at": null
}
```

Ответы с карточкой включают упорядоченные массивы `assignee_ids` и `assignees`.
Поля `assignee_id` и `assignee` по-прежнему возвращают основного исполнителя.
В REST и MCP массив `assignee_ids` заменяет весь список, первый элемент
становится основным. Пустой массив снимает все назначения. Пропуск поля
сохраняет список при обновлении. Список принимает только существующих
пользователей без повторов.

Старое поле `assignee_id` заменяет основного исполнителя, сохраняя остальных.
При обновлении значение `null` снимает основное назначение. Следующий исполнитель
становится основным. Массив и старое поле назначения передаются раздельно.

Пример перемещения:

```json
{
  "expected_version": 7,
  "target_column_id": "uuid",
  "before_card_id": "uuid"
}
```

Вместо `before_card_id` можно передать `after_card_id`; одновременная передача обоих полей запрещена. Без них карточка становится последней в целевой колонке.

### 4.5. Вложения

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/cards/{id}/attachments` | `multipart/form-data` с одним полем `file` |
| `POST` | `/epics/{id}/attachments` | `multipart/form-data` с одним полем `file` |
| `GET` | `/attachments/{id}` | Скачать файл с проверкой авторизации |
| `DELETE` | `/attachments/{id}` | Удалить метаданные и файл |

В базе хранятся только метаданные. Имя файла на диске генерируется сервером и не зависит от пользовательского имени. Корневой каталог и максимальный размер задаются конфигурацией. Расширение и заголовок `Content-Type` не считаются достаточной проверкой типа.

### 4.6. Комментарии

| Метод | Путь | Назначение |
|---|---|---|
| `GET, POST` | `/cards/{id}/comments` | Прочитать или добавить комментарий к карточке |
| `GET, POST` | `/epics/{id}/comments` | Прочитать или добавить комментарий к проекту |

Комментарии поддерживают Markdown. В ответе возвращаются автор и, если комментарий создан агентом, `author_token_id`.

### 4.7. Персональные API-токены

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/tokens` | Показать свои токены без секрета |
| `POST` | `/tokens` | Выпустить токен |
| `DELETE` | `/tokens/{id}` | Отозвать свой токен |

Токен имеет формат `jkb_pat_<random>` и не менее 256 бит случайности. Полное значение возвращается ровно один раз в ответе `POST /tokens`. В базе хранятся отображаемый префикс и SHA-256 digest полного токена.

Допустимые scopes:

- `cards:read`;
- `cards:write`.

`cards:write` не подразумевает `cards:read`: для обычного агента выдаются оба scope. Токен наследует роль и активность владельца. Отозванный, просроченный или принадлежащий неактивному пользователю токен недействителен.

## 5. MCP API

### 5.1. Транспорт и auth

- endpoint: `/mcp`;
- transport: stateless Streamable HTTP;
- целевая версия протокола: `2026-07-28`;
- аутентификация: `Authorization: Bearer jkb_pat_...`;
- MCP endpoint не принимает cookie-сессии;
- сервер не выдаёт OAuth-токены в MVP;
- клиент должен уметь передать статический Bearer token.

Реализация опирается на официальные [MCP specification](https://modelcontextprotocol.io/specification/2026-07-28) и [MCP Go SDK](https://go.sdk.modelcontextprotocol.io/). Если целевая версия ещё не поддержана стабильным Go SDK, сервер временно поддерживает последнюю совместимую версию, не меняя схемы инструментов.

### 5.2. Инструменты чтения

| Tool | Аргументы | Результат |
|---|---|---|
| `get_current_user` | — | Владелец токена, его группы, роль, ID токена и scopes |
| `list_columns` | — | Все колонки по позиции |
| `list_epics` | `include_archived?` | Проекты |
| `get_epic` | `epic_id` | Проект с описанием и количеством задач |
| `list_groups` | — | Группы |
| `list_users` | `group_id?`, `include_inactive?` | Пользователи без чувствительных полей |
| `list_tags` | — | Теги |
| `list_cards` | Фильтры REST API, `limit?`, `cursor?` | Краткие DTO карточек и `next_cursor` |
| `get_card` | `card_id` или `card_number` | Полная карточка с тегами и метаданными вложений |
| `get_card_activity` | `card_id`, `limit?`, `cursor?` | Журнал карточки |
| `list_card_movements` | `from?`, `to?`, `actor_user_id?`, `assignee_id?`, `project_id?`, `group_id?`, `card_id?`, `limit?`, `cursor?` | Перемещения карточек за период и `next_cursor` |
| `list_comments` | Ровно одно из `card_id`, `project_id` | Комментарии карточки или проекта |

`get_current_user` доступен любому валидному токену. Остальные инструменты чтения требуют
`cards:read`; все они помечаются MCP annotation `readOnlyHint: true`.

Перед выбором задачи агент вызывает `get_current_user`. Для поиска своих задач можно передать
`assignee_id="me"` в `list_cards`. Перед началом работы над карточкой или проектом агент вызывает
`list_comments`, так как обсуждение может содержать актуальные требования и решения.

`list_card_movements` без `from` и `to` возвращает движения за предыдущие 24 часа. Границы периода
задаются в RFC 3339; `from` включается, `to` не включается. Без пользовательских фильтров отчёт
охватывает всю доску. `actor_user_id` означает пользователя, выполнившего перемещение,
`assignee_id` — любого текущего исполнителя карточки; оба фильтра принимают значение `me`. В результате
возвращаются названия карточек и колонок, инициатор и использованный им API-токен, текущие
исполнители, проект и группа. `current_assignees` содержит упорядоченный список всех текущих
исполнителей (пустой массив для неназначенной карточки), а совместимое поле `current_assignee` —
основного исполнителя. Оба поля отражают текущие назначения, а не исторический снимок
на момент перемещения.

`add_comment` принимает ровно одно из `card_id`, `project_id`, а также `body`, и требует `cards:write`.

`create_epic` и `update_epic` требуют `cards:write` и роль `admin` владельца токена.

### 5.3. Инструменты изменения

| Tool | Обязательные аргументы | Опциональные аргументы |
|---|---|---|
| `create_card` | `title`, `column_id` | `description`, `epic_id`, `group_id`, `assignee_id`, `assignee_ids`, `tag_ids`, `due_at` |
| `update_card` | `card_id`, `expected_version` | `title`, `description`, `epic_id`, `group_id`, `assignee_id`, `assignee_ids`, `tag_ids` |
| `move_card` | `card_id`, `expected_version`, `target_column_id` | `before_card_id` или `after_card_id` |
| `assign_card` | `card_id`, `expected_version` | `group_id`, `assignee_id`, `assignee_ids` |
| `archive_card` | `card_id`, `expected_version` | — |
| `restore_card` | `card_id`, `expected_version` | — |

Все инструменты изменения требуют `cards:write`. Успешная мутация возвращает полную обновлённую карточку, включая новую `version`.

MCP-инструменты вызывают тот же доменный слой, что и HTTP API. Они не дублируют бизнес-правила и не обходят журнал изменений. Каждая MCP-мутация сохраняет `actor_user_id` и `actor_token_id`.

### 5.4. MCP-ошибки

Ожидаемые ошибки возвращаются как ошибка tool result с машинными `code` и `details`. Минимальный набор:

- `unauthenticated`;
- `insufficient_scope`;
- `not_found`;
- `validation_failed`;
- `card_version_conflict`;
- `rate_limited`;
- `internal_error`.

При `card_version_conflict` в `details` возвращаются текущие `version` и карточка, чтобы агент мог перечитать состояние и осознанно повторить операцию.

## 6. Хранение и развёртывание

- приложение работает одним Go-процессом;
- собранный Vue frontend встраивается в Go-бинарник;
- SQLite — единственная поддерживаемая база данных; приложение использует pure-Go драйвер `modernc.org/sqlite`;
- поддерживается ровно один экземпляр приложения, работающий с базой на локальной файловой системе;
- файл SQLite нельзя размещать на NFS, SMB и других сетевых файловых системах;
- путь базы задаётся `JKB_DATABASE_PATH`; локальное значение по умолчанию — `./storage/jkb.sqlite`, в контейнере — `/var/lib/jkb/jkb.sqlite`;
- база, её WAL-файлы, вложения и аватары хранятся внутри единого data root; production Compose монтирует `/var/lib/jkb` одним persistent volume;
- HTTP API, frontend и MCP слушают один порт;
- для публичного доступа обязателен TLS на reverse proxy;
- `/health/live` проверяет жизнь процесса, `/health/ready` — доступность SQLite и каталога файлов.

SQLite открывается с foreign keys, WAL, ограниченным ожиданием writer lock и согласованным режимом синхронизации. Резервная копия полна только при совместном сохранении согласованного snapshot базы и локальных файлов.

PostgreSQL runtime, второй SQL-диалект и production-импорт PostgreSQL не поддерживаются. Существующие PostgreSQL volumes и backup-архивы не являются входными данными для SQLite-релиза.

## 7. Нефункциональные требования

- пароли хешируются Argon2id;
- сессии и API-токены можно отозвать без перезапуска;
- в логи не попадают пароли, cookie, Authorization header и тела файлов;
- login и неуспешная Bearer-аутентификация имеют rate limiting;
- мутация карточки и запись activity выполняются в одной транзакции;
- тихая потеря изменений при конкурентном редактировании недопустима;
- сервис должен корректно завершать активные HTTP-запросы при graceful shutdown;
- миграции базы версионируются и выполняются явно перед запуском новой версии.

### Публичное оформление web-приложения

`GET /manifest.webmanifest`, `/favicon.svg`, `/favicon.ico`,
`/apple-touch-icon.png`, `/icon-192.png`, `/icon-512.png`, `/icon-maskable.png`
доступны без сессии и возвращают только публичное оформление экземпляра.
Manifest содержит стабильный `id: /`, standalone-режим, имя из `JKB_SYSTEM_NAME`
и ссылки на иконки с отпечатком настроек. Ответы допускают перепроверку кеша
(`Cache-Control: no-cache`). SVG, ICO, PNG и manifest имеют соответствующий
Content-Type; неизвестные API/MCP пути сохраняют прежнюю семантику ошибок.
HTML клиентских маршрутов содержит экранированное имя до выполнения JavaScript.

`JKB_ICON_COLOR` — необязательная runtime-настройка фона иконок: `#RRGGBB`,
по умолчанию `#2563EB`. Отсутствующее, пустое или состоящее из пробелов значение
совместимо со старой конфигурацией; непустое некорректное значение препятствует
запуску. Цвет знака выбирается автоматически по контрасту. Изменение env требует
перезапуска с новым окружением, но не пересборки образа или миграции данных.
`GET /api/v1/system` сохраняет текущую схему `{ "name": "…" }`.

## Автоархивация и единый архив

Общий `done_column_id` определяет завершённость карточек и прогресс проектов независимо от порядка колонок. Учитываются все связанные карточки, включая архивные. Проект завершён только при `card_count > 0 && completed_card_count == card_count`; округлённые проценты не используются. Удалять выбранный столбец нельзя до изменения настройки.

Политика доски содержит `version`, `done_column_id`, `cards_enabled`, `cards_days`, `projects_enabled`, `projects_days`. Два правила выключены первоначально, сроки по умолчанию 3, допустимы целые 1–3650 дней. День — 24 часа UTC. Изменения требуют `expected_version`; конфликт не перезаписывает чужую настройку. Предпросмотр показывает количество кандидатов без мутации.

Срок карточки начинается при входе в выбранный столбец, включая создание в нём. Выход и повторный вход начинают срок заново; перестановка внутри столбца, изменение текста и комментарии срок не меняют. Проект хранит начало непрерывной завершённости; новая незавершённая карточка сбрасывает его. Смена выбранного столбца начинает отсчёт заново. Изменение длительности или включение правила учитывает накопленное время. Неизвестные сроки существующих объектов начинаются при миграции.

Обработчик единственного Go-процесса проходит при запуске и каждые пять минут: сначала проекты, потом карточки. Условие проверяется повторно в write-транзакции. Достижение срока означает право на архивацию, фактический переход происходит на очередном проходе. Миграции запускаются только явно. Backup/restore исключает одновременную работу обработчика.

Архивация проекта атомарно архивирует оставшиеся активные карточки с общим идентификатором группы. Восстановление требует версии проекта и явного режима `project_only` или `with_cards`. Второй режим возвращает только карточки актуальной группы, которые всё ещё архивны и принадлежат этому проекту. Ранее отдельные архивации и повторно архивированные карточки не затрагиваются. Конфликт имени активного проекта отменяет всю операцию. Восстановление начинает новый срок автоархивации; столбец карточки сохраняется.

Участники читают архив и восстанавливают карточки; проекты и настройки изменяет только администратор. MCP дополнительно проверяет `cards:read` / `cards:write`. Все пути используют общие доменные операции. Изменения проектов требуют `expected_version`. Архивные объекты доступны для чтения, обычное редактирование требует восстановления. Нельзя добавлять активную карточку в архивный проект или восстанавливать его отдельную карточку: сначала следует восстановить проект.

Журнал содержит сущность, действие, время, причину (`manual`, `automatic`, `legacy`), инициатора (`user`, `system`, `unknown`), группу операции и снимок названия/номера. Автоматика не выдаётся за пользователя; её `actor_user_id` равен null. Повторная команда без перехода не создаёт событие. Достоверные старые события карточек сохраняются; неизвестная дата старого проекта отображается как неизвестная.

Архив по умолчанию показывает текущие архивные объекты по последней архивации; режим истории включает восстановления и прошлые циклы. Проектная операция группирует дочерние карточки. Выдача курсорная, упорядочена по времени и уникальному ID, поддерживает тип сущности, проект, текст, период и состояние. Неизвестные даты идут отдельно после известных. Ответ включает актуальное состояние и версию для восстановления.

### Archive API

| Метод | Путь | Доступ / вход |
|---|---|---|
| GET | `/api/v1/archive` | member; `type=card/project`, `project_id`, `q`, `from`, `to` (RFC3339, полуинтервал), `history`, `state=archived/restored/all`, `batch_id`, `cursor`, `limit` (1–100) |
| GET | `/api/v1/archive/policy` | member |
| PUT | `/api/v1/archive/policy` | admin; поля политики и `expected_version` |
| POST | `/api/v1/archive/policy/preview` | admin; предлагаемая политика |
| POST | `/api/v1/epics/{id}/restore` | admin; `expected_version`, `mode=project_only/with_cards` |

`GET /epics/{id}` также возвращает `version` и `restorable_cards`. Старый `PATCH /epics/{id}` использует общую транзакцию; требует `expected_version`, при восстановлении — `restore_mode`. Создавать проект сразу архивным нельзя. MCP `update_epic` принимает те же поля, `list_archive` — фильтры архива (`cards:read`), `restore_epic` — `epic_id`, `expected_version`, `mode` (admin + `cards:write`). Настройки не изменяются через MCP.

Список архива возвращает `{items,next_cursor}`. Запись: `id` (непрозрачный идентификатор события), `entity_type`, `entity_id`, `project_id`, `action`, `occurred_at` (nullable), `reason`, `actor_type`, `actor_name`, `batch_id`, `title`, `number`, `rule_days`, актуальные `is_archived`, `version`, `child_count`, `restorable_cards`. `batch_id` позволяет раскрыть карточки группы с отдельной пагинацией; фильтр `type=card` показывает карточки самостоятельно. `history=true` включает прошлые события; `state` фильтрует актуальное состояние объекта. Предпросмотр возвращает `{cards,projects}`; число карточек включает карточки проектов-кандидатов и не складывается с числом проектов.

Конфликты HTTP 409: `project_version_conflict`, `archive_version_conflict`, `project_archived` (сначала восстановить проект), `object_archived` (сначала восстановить объект), `project_name_conflict`, `done_column_selected`. Неверный срок, столбец, режим или курсор — 422 `validation_failed`. Архивные объекты нельзя изменять, дополнять комментариями или изменять их вложения.
