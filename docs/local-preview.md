# Локальный просмотр изменений

Миграции выполняются явно через `docker compose exec app /usr/local/bin/jkb-migrate up`, после чего приложение перезапускается. Собирать нужно текущий код командой `docker compose build app`, а не скачивать latest.

Миграция политики столбцов сохраняет разрешение для существующих столбцов. Администратору нужно открыть настройки колонок и выключить «Разрешать создание карточек» у рабочих/завершённых этапов. Новые столбцы создаются с выключенным разрешением. Можно оставить создание запрещённым везде.

Для отдельного preview используйте отдельное имя compose-проекта, локальный тег образа, свободный порт на loopback и отдельный volume. Не останавливайте неизвестный сервис на занятом порту. Для HTTP на localhost нужен JKB_COOKIE_SECURE=false. Production-данные и существующие токены для проверки не нужны. Не выполняйте destructive rollback без отдельного решения и резервной копии.

## Аккаунты ботов

После явного применения миграции 8 существующие пользователи сохраняют тип human и свои PAT. Создавайте агентов в «Настройки системы → Боты». Укажите имя, сохраните выданный один раз токен и настройте его как Bearer для `/mcp`. Оба scope включены постоянно; веб-пароля у бота нет. Имя и аватар редактируются администратором. Бот появляется в списке исполнителей со своим ID.

Перевыпуск немедленно отзывает предыдущий токен. Подтвердите действие в диалоге, скопируйте новый токен и замените его в MCP-клиенте. Если ответ потерян, повторно прочитать секрет нельзя: откройте перевыпуск заново и выполните новую ротацию. Конкурентная попытка возвращает конфликт и не отзывает только что выданный токен автоматически.

Отключение бота сохраняет карточки и историю, но блокирует его MCP-доступ; включение возвращает доступ последнему неотозванному токену. MCP-клиент может закрыть соединение после отказа авторизации; после включения при необходимости подключите его заново. Имя можно менять без потери авторства. У обычных пользователей по-прежнему может быть несколько персональных токенов.

Резервная копия содержит SQLite и локальные аватары; для восстановления требуется совпадающая версия схемы. Миграция 8 не перестраивает users и не меняет существующие внешние ключи. Откат при наличии ботов намеренно запрещён: используйте согласованную процедуру восстановления из резервной копии, а не удаление истории агентов.
